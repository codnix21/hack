# Запуск платформы

## Какой UI показывать заказчику (единственная актуальная версия)

| Адрес | Что это | Когда актуален |
|-------|---------|----------------|
| **http://127.0.0.1:8910** | nginx в Docker (`bas-frontend`) | **Единственная демо-версия для защиты.** `frontend/dist` монтируется через `docker-compose.override.yml`. Собирать только `npm run build:demo` (ставит `VITE_API_URL=/api`). |
| http://127.0.0.1:5173 | Vite dev | Только разработка. Proxy `/api` → `127.0.0.1:8010`. Не показывать заказчику. |
| http://127.0.0.1:8010 | FastAPI | Backend. С UI `:8910` браузер ходит на same-origin `/api` (nginx → backend). |

**Правило защиты:** открывать только `http://127.0.0.1:8910`. Порт `5173` — не демо.

### Воспроизводимый запуск актуальной версии (без сброса БД)

```powershell
# 1) Стек Docker (том pgdata сохраняется)
cd C:\Users\death\Desktop\hack
docker compose up -d

# 2) Актуальный UI для nginx (:8910) — обязательно build:demo
cd frontend
npm install
npm run build:demo

# 3) Подхватить dist (pgdata не трогаем)
cd ..
docker compose up -d frontend

# 4) Проверка
curl http://127.0.0.1:8010/health
# демо: http://127.0.0.1:8910
```

Команда `npm run build` без `build:demo` может собрать UI с API на `localhost:8000` — на `:8910` гостевой вход сломается. Для демо всегда `build:demo`.

Не используйте `docker compose down -v` — том `pgdata` будет уничтожен.

### Если `docker compose build` падает

Фактическая ошибка в этой среде: Docker Desktop ходит в registry через **HTTPS proxy `http://127.0.0.1:10801`**, соединение отклоняется (`connection refused`). Образы `hack-frontend` / `hack-backend` при этом уже есть локально (старые), пересборка с Docker Hub невозможна без исправления proxy в Docker Desktop.

**Проверенная альтернатива (TLS не отключаем):**

1. Не пересобирать образы.
2. Монтировать актуальный код backend и `frontend/dist` через `docker-compose.override.yml` (уже в репозитории).
3. Собирать UI командой `npm run build:demo` на хосте.

### Если DXF в Docker отвечает «библиотека не установлена»

Образ backend может быть без `ezdxf`. PyPI из контейнера тоже может падать по SSL. Проверенный обход: скачать manylinux-wheels на хосте и установить в контейнер — см. `backend/scripts/install_ezdxf_in_container.md`. После `docker compose up --force-recreate backend` пакет нужно поставить снова (том `pgdata` не затрагивается).

## Docker Compose (полный сценарий при доступном registry)

```bash
docker compose up -d --build
```

| Сервис | Порт | Описание |
|--------|------|----------|
| frontend | `127.0.0.1:8910` | UI (nginx) |
| backend | `127.0.0.1:8010` | FastAPI |
| db | `127.0.0.1:5435` | PostgreSQL, том `pgdata` |

Порты: `.env` → `FRONTEND_PORT`, `BACKEND_PORT`, `POSTGRES_PORT`.

При старте backend: миграции, seed, идемпотентная очистка истёкших гостей.

### Очистка гостевых проектов

```bash
python scripts/cleanup_guests.py   # из каталога backend
# или POST /api/admin/cleanup-guests
```

Периодичность: ежедневно. Повторный запуск безопасен.

### Остановка без потери данных

```bash
docker compose down
# НЕ добавляйте -v
```

## Vite (только разработка)

```powershell
cd frontend
npm run dev -- --host 127.0.0.1 --port 5173
# proxy /api → http://127.0.0.1:8010
```

## Тесты

```powershell
# Backend
cd backend
pytest tests -q

# Frontend
cd frontend
npm test
npm run build
# по умолчанию E2E бьёт в http://127.0.0.1:8910
npm run test:e2e
```

Перед Playwright на `:8910` выполните `npm run build:demo` и `docker compose up -d frontend`.
